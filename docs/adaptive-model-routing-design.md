# 运行中模型切换与自适应 Provider 设计

状态：设计草案，尚未实现。

## 背景与目标

目前有两个候选模型：

- 普通模型：`ark/deepseek-v4.1-flash`
- 低成本模型：`ark/deepseek-v4.1-flash-economy`

本设计以两者效果相同为业务前提。economy 的主要区别是调用延迟较高，但低峰期延迟可能接近普通模型。目标是在控制任务延迟的同时，尽量使用 economy 降低成本。

需要提供两层能力：

1. 正在运行的任务可以切换模型，下一次推理请求生效，无须重启任务。
2. 新增 `adaptive` provider，根据时间窗口和实际请求延迟，在两个候选模型之间自动选择。

首版仅支持明确配置的这组等价模型，不做模型质量评分、不推断任意模型是否等价，不做重复请求竞速，也不扩展为通用多模型竞价系统。

## 现有代码基础

- `crates/openduck/src/agents/agent.rs`：`update_provider()` 支持更换 provider 并持久化 session 模型配置；`model_config_for_session()` 以 session 配置作为模型配置来源。
- `crates/openduck-provider-types/src/base.rs`：`Provider::stream()` 每次接收 `ModelConfig`，适合逐请求选择模型；默认 `complete()` 通过流收集结果，并包含重试。
- `crates/openduck/src/agents/reply_parts.rs`：旧路径的流请求和错误恢复入口。
- `crates/openduck/src/agents/state_machine/ops_llm.rs`：状态机推理入口；`InferenceRunner` 持有 provider 和模型配置快照。

已有更新接口不代表运行中任务的下一次请求必然读取新配置。需要检查并消除运行期间过早固定配置的情况，同时保留单次请求内配置的一致性。

旧 agent loop 和 `OPENDUCK_STATE_MACHINE=1` 路径必须一起实现和验证。

## 动态切换语义

切换以模型请求为边界：

- 当前响应流继续完成，不在流中途替换模型。
- 已发出的工具调用继续执行，保留工具调用 ID、工具结果和完整会话历史。
- 下一次推理请求读取最新路由配置，包括同一轮任务中工具执行后的后续推理。
- 同一请求一旦选定模型，保持到请求结束。

需要区分以下状态：

| 状态 | 含义 |
| --- | --- |
| 用户选择 | 固定普通、固定 economy、自动 |
| 自动策略主模型 | 当前大多数请求使用的模型 |
| 本次实际模型 | 当前请求使用的模型，可能是对侧探测 |

探测不能改写用户选择。用户手动固定模型后，后续请求立即服从固定选择；此前已启动的探测可以完成，但不能把模式切回自动或覆盖新的主模型选择。

### 共享路由句柄

引入任务级共享路由句柄，两套 agent loop 都在每次推理前从句柄获取不可变请求快照。快照将 provider、模型配置、模式和配置版本绑定，避免分开读取产生不一致。

运行中更新采用以下顺序：

1. 校验并准备候选配置及底层 provider。
2. 持久化用户选择；失败时保持现有生效配置。
3. 发布新的完整运行时配置快照，并返回生效版本。

任务运行期间的配置更新应串行处理。请求只在开始时短暂读取快照，不能在网络等待或消费响应流时持有配置锁。

策略决策与观测附带配置版本。旧版本请求的结果不得改变新版本的选择。会话恢复时从持久化配置重建句柄；首版不持久化延迟样本和冷却状态。

## 自适应策略

采用“主模型 + 对侧探测 + 切换冷却”。时间窗口用于初始选择和缺少数据时的默认值，近期健康与延迟数据可以覆盖时间偏好。

以下参数仅为试运行初值，不是已有性能结论：

| 参数 | 初值 |
| --- | --- |
| 时区 | `Asia/Shanghai`，显式配置 |
| 低峰窗口 | 每日 01:00–07:00，可配置，支持跨午夜 |
| 无新鲜数据时 | 低峰选择 economy，其他时间选择普通 |
| 对侧探测比例 | 约 10%，加入随机扰动 |
| 统计窗口 | 最近 15 分钟，每模型最多 30 个有效样本 |
| 最小样本 | 两侧各至少 3 个可比较样本 |
| 切换确认 | 连续两次有新增有效样本的评估满足条件 |
| 切换冷却 | 5 分钟 |
| economy 严重超时后的暂停时间 | 5 分钟，之后允许一次恢复探测 |

### 时间策略

1. 进入低峰窗口时，优先切到 economy；近期已有严重变慢或不可用证据时继续使用普通。
2. 离开低峰窗口时，重新评估新鲜样本。economy 仍满足延迟预算则继续使用；证据不足时回到普通。
3. 时间窗口边界只处理一次，不能每次请求重复强制选择，从而覆盖健康决策。

### 双向探测与切换

普通为主时，将少量正常请求交给 economy。economy 为主时，将少量正常请求交给普通。探测直接承担任务下一次推理，不额外复制请求，因此不会因探测重复消耗一份输入输出 token。

在可比较样本充足时，初始切换判据为：

- 切到 economy：估计延迟不超过普通的 1.25 倍，且增加不超过 2 秒。
- 切到普通：economy 估计延迟超过普通的 1.6 倍，且增加超过 3 秒。

两项条件均需满足。两个方向的阈值不同，配合连续确认和冷却防止抖动。普通切换受冷却限制；严重超时和可用性故障允许立即退出不健康候选。

探测应限制同时在途数量，首版每任务最多一个。低请求量时可能长时间无法获得足够证据，此时保持时间默认值或当前健康选择，不制造额外请求补样本。

### 延迟测量

不能把 `stream().await` 返回耗时视为首输出延迟，也不能直接比较不同长度响应的总完成时间。

每个请求记录：

- 从请求开始到首个有效输出的时间；忽略心跳、空事件和仅含 usage 的事件，推理内容或工具调用有效片段计入。
- 总完成时间、输入与输出 token、可获得的缓存命中信息。
- 实际模型、主调用或探测、配置版本、尝试次数、错误及取消状态。

主要依据是相近输入规模请求的首个有效输出延迟，输出速度和总完成时间作为辅助约束。首版对输入 token 规模分桶，在桶内使用指数平滑；只有两侧存在新鲜、足量的可比较样本时才进行性能切换。分桶边界、平滑系数以及输出速度保护阈值在实现前通过采样确定，并纳入策略配置或明确默认值。

超时单独计入故障统计，不能只统计成功请求造成幸存者偏差。用户主动取消不计为模型故障。重试后的请求需保留尝试耗时，不能将包含退避和多次重试的总耗时混入单次成功延迟样本。

样本过期后不沿用旧比较结论。流被提前丢弃时也要结束观测，标记取消或未完成，释放探测配额。

## AdaptiveProvider 职责与接入

建议在 `crates/openduck-providers/` 内新增实现模块，并在 `crates/openduck/src/providers/` 的工厂与配置层注册；最终路径遵循现有依赖方向。

`AdaptiveProvider` 包装底层 provider 和两个完整候选 `ModelConfig`，不复制已有 HTTP 客户端和认证逻辑。每次 `stream()` 选择候选、委托调用，再包装返回流采集观测。

职责划分：

- 共享路由句柄：处理用户运行中更新，保证请求快照一致。
- 策略模块：纯决策逻辑，输入时间、统计和当前状态，输出路由决定及原因。
- 观测模块：消费流时测量首输出、完成、错误与取消。
- provider 包装层：委托实际请求，保留底层能力和 usage。
- agent 集成层：在两套 loop 的请求边界读取配置，传播实际路由信息。

兼容性要求：

- 显式验证工具调用、上下文、推理参数等兼容性。自动模式使用两者共同支持的上下文和能力限制。
- `complete()`、压缩和其他辅助调用也需审查。首版主循环参与探测和学习，辅助调用沿用当前健康主模型，但不混入主循环延迟样本；通过请求用途显式区分。
- usage 和计费保留实际模型，session 中的用户选择保持自动模式。
- 外层请求跨度展示用户选择，实际调用跨度记录真实 provider 和模型，避免把 `adaptive` 当作计费模型。
- 首版统计按任务隔离。后续再考虑按账号、端点和策略分组共享统计，不能跨凭证混用健康结论。

### 错误恢复

与已有重试机制统一请求预算，避免 provider 包装层与 agent 各自多次重试。

- 尚未输出有效内容时，可按错误类型进行有限回退；首版每次逻辑请求最多一次跨模型回退，且受总体重试预算约束。
- 已输出有效内容后，不拼接其他模型响应。遵循现有错误恢复流程，下一次请求重新选择模型。
- 认证、参数和配置错误直接报告，不通过反复切换掩盖问题。
- 两个候选均不可用时按既有错误路径终止或返回可恢复错误，不无限循环。

## 拟议配置与展示

下面仅表达语义，不代表已有配置 schema。接入时需适配仓库的 provider 配置系统，并明确 `ark/` 是候选标识中的 provider 前缀还是上游实际模型名，不能未经解析直接发送。

```yaml
provider: adaptive
policy:
  timezone: Asia/Shanghai
  off_peak: ["01:00-07:00"]
  probe_ratio: 0.10
  cooldown_seconds: 300
candidates:
  regular: ark/deepseek-v4.1-flash
  economy: ark/deepseek-v4.1-flash-economy
```

第一版提供最小配置和运行中更新入口，支持固定普通、固定 economy、自动三种选择。状态展示包含当前模式、主模型、本次实际模型、是否探测、最近一次切换原因和生效版本。自动切换通过结构化状态或事件呈现，避免为每次请求新增普通日志。

## 实施计划

| 阶段 | 实施内容 | 验收标准 |
| --- | --- | --- |
| 1：动态切换基础 | 共享路由句柄、配置版本、请求边界快照、运行中更新、两套 loop 接入 | 同一运行任务更新后下一次请求使用新模型，响应流和工具链保持完整 |
| 2：自动 provider | 候选包装、流观测、真实请求探测、时间策略、阈值、冷却、有限回退 | 模拟时钟与延迟序列可复现低峰启用、双向切换、防抖和故障退出 |
| 3：配置与展示 | provider 注册、配置校验、最小状态展示与手动固定入口 | 用户能查看实际模型及选择原因，手动固定不会被旧探测覆盖 |
| 4：真实流量试运行 | 显式启用、采集成本与延迟、调整初始参数 | economy 使用比例提高，任务延迟满足试运行前约定的预算 |

建议首次交付覆盖阶段 1、2 和阶段 3 的最小入口，完整 UI 后续扩展。

## 验证计划

测试优先放在对应 crate 的 `tests/` 中；必要的状态机集成测试遵循已有组织方式。

1. 动态切换：流中更新、工具执行中更新、下一次请求生效、持久化失败、任务恢复、并发更新和旧配置结果隔离。
2. 两套 loop：使用相同场景验证模型选择序列和会话历史一致。
3. 时间策略：进入及离开低峰、跨午夜窗口、显式时区、样本过期、健康状态覆盖时间偏好。
4. 决策算法：最小样本、不同比例与绝对阈值、连续确认、冷却、稀疏流量和探测并发限制。
5. 流与故障：慢首输出、快速首输出但慢完成、空事件、推理及工具片段、流中错误、超时、取消、流丢弃和两个候选均不可用。
6. 兼容性：上下文限制、工具调用 ID、推理参数、实际模型 usage、辅助调用隔离及总体重试预算。
7. 补充 `openduck-self-test.yaml`，覆盖固定与自动选择的基础场景。

实施中执行 `cargo fmt`。按照仓库规则，在用户要求构建或测试后执行相关构建、crate 测试、clippy，以及重建后的 recipe 自测；合并前必须完成 clippy。

真实流量验证前先约定可接受的任务耗时增幅与首输出延迟上限，再比较固定普通与自动模式的实际成本、economy 使用比例、请求和任务耗时分位数、超时率、探测比例及切换频率。单次任务比较受任务内容影响，需结合足量样本评估。回滚方式为将用户选择固定到普通模型，下一次请求生效。

## 实现前需确定的参数

- 实际低峰窗口和任务可接受的延迟预算。
- 首输出分桶、平滑系数及慢输出保护阈值。
- 现有 ark 配置中的候选标识解析方式及两模型能力元数据。

上述参数不阻止先实现动态切换基础，但自动策略上线前需明确。初始配置必须显式启用，不改变现有任务默认 provider。
