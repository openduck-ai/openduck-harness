# TUI agent proxy reconnaissance

Recon only. No source edits, builds, or tests performed. References are repository-relative `file:line` locations at inspection time. Recommendations below are proposals, not existing behavior.

## 1. Which configuration and process?

**Recommendation: target the core OpenDuck agent configuration, adding top-level `proxy` to `config.yaml`, if the requested behavior is configuring OpenDuck's own model HTTP client.** Do not mistake the harness TUI subprocess configuration for an in-process model client. Both sections can physically occupy `~/.config/openduck/config.yaml`; they are different consumers with different discovery rules.

- Candidate (a): `crates/openduck-harness/src/types.rs:254` defines `TuiSessionDefaults`; `:258` has `https_proxy`, not `proxy`. `HarnessGlobalSettings` at `:276` contains `tui_sessions` at `:332`. This configures external CLI sessions. `crates/openduck-mcp/src/tui_session/profiles/mod.rs:26` defines `AgentCliKind`; `:103` defines `TuiSessionConfig`, with `https_proxy` at `:115`. Session startup at `crates/openduck-mcp/src/tui_session/session.rs:453` discovers harness defaults using `cwd`. At `:477` it resolves request setting > agent-kind defaults > `default`. At `:514` it builds the external launch command, and at `:520–543` it injects uppercase AND lowercase HTTP_PROXY, HTTPS_PROXY, ALL_PROXY (six variables). Empty/whitespace or literal `direct` produces six empty variables; otherwise the original string is forwarded. It removes matching entries from the supplied session env first. `:547` onward calls backend `spawn_pane`. This layer owns no model HTTP transport. For third-party CLIs, their implementations—not this repository's ApiClient—own model requests.
- Candidate (b): `crates/openduck/src/config/base.rs:145` defines `Config`, an ordered-path dynamic YAML mapping, **not a serde struct enumerating every core config field**. `:254` defines `config_value!`; the two-argument form generates get/set methods calling `get_param`/`set_param` with the literal identifier key. The camel conversion at `:319` creates a Rust wrapper type for the three-argument form; it does NOT create camelCase YAML aliases. `:1307–1316`, `:1393–1396` show real declarations (uppercase legacy keys remain common).
- Model HTTP calls are in providers. Legacy loop delegates to provider completion at `crates/openduck/src/agents/agent.rs:3998`; state-machine LLM work resides in `crates/openduck/src/agents/state_machine/ops_llm.rs:1`, with Provider dependencies at `:15` and provider state at `:115`. OpenAI's request dispatch is `crates/openduck-providers/src/openai.rs:330–338` and `:840–852`; Anthropic streaming is `crates/openduck-providers/src/anthropic.rs:188–191`; Google streaming is `crates/openduck-providers/src/google.rs:115–118`. Neither loop is the HTTP-client integration point. MCP tool transports are a separate concern; configuring model ApiClient does not establish an all-MCP/all-network guarantee.

There is no unique standalone “TUI agent config” schema identified by the task phrase alone. If the intended subject is specifically a spawned Grok/Claude/Codex CLI, candidate (a) is its harness configuration, but a direct Rust model-client guarantee cannot be implemented there for those external executables. This is a scope distinction, not a reason to silently change both schemas.

## 2. Schema, file locations, and precedence

### Core

- `base.rs:100–144` documents YAML, dynamic keys, snake_case recommendation, and product-prefixed env compatibility. `base.rs:803–822` implements generic retrieval: env first, then exact mapping key; it deserializes YAML values and can retry string contents through its env-value parser. File key lookup is case-sensitive; snake_case is a convention, not an automatic alias conversion.
- `crates/openduck/src/config/env.rs:42–60` implements OPENDUCK_suffix before GOOSE_suffix. `:75–81` implements `env_lookup`: an unprefixed key tries OPENDUCK_KEY, GOOSE_KEY, raw uppercase KEY; a product-prefixed key uses only the dual product lookup. Thus generic `get_param("proxy")` would allow OPENDUCK_PROXY, GOOSE_PROXY, PROXY to override a file value. That is a design choice to reconcile with “proxy env vars only as fallback,” not an implementation of file-first precedence.
- `base.rs:59` names `config.yaml`. Default path order at `:215–221` is system, additional files, user; later files win. `:173–185` defines `/etc/goose/config.yaml` on Unix and ProgramData/goose/config.yaml on Windows. `:189–193` gets additional files from OPENDUCK_ADDITIONAL_CONFIG_FILES / GOOSE_ADDITIONAL_CONFIG_FILES via platform path-list splitting. `:335` recursively merges config mappings; `:557` loads paths in order. `:488` also permits explicit ordered paths.
- `crates/openduck/src/config/paths.rs:248` returns `Paths::config_dir()`. `:195–207` maps an absolute PATH_ROOT override to `<root>/config`; `:226–241` gives OPENDUCK_PATH_ROOT precedence over GOOSE_PATH_ROOT and rejects relative values. `:14–41` uses etcetera's platform strategy with app name OpenDuck; `:209–221` migrates/falls back to legacy goose directories. The documented Linux location is `~/.config/openduck/config.yaml`; do not hard-code it across platforms.
- **Important discrepancy:** `Config::default` does not itself append workspace `.openduck/config.yaml`. The broad docs precedence list (`documentation/docs/guides/config-files.md:532–534`) must not be substituted for this constructor's actual path list.

### Harness

- `types.rs:253–273`: snake_case serialized fields, defaulted optional values omitted when None; `https_proxy` accepts `httpsProxy`. `HarnessGlobalSettings.tui_sessions` accepts `tuiSessions` (`:331–332`). Project provider schema instead uses struct-wide camelCase (`crates/openduck-harness/src/project/config.rs:11–27`), with explicit snake aliases for multiword model fields; `proxy` has identical spelling in both styles.
- `types.rs:178–243` enumerates discovery paths, highest priority first: OPENDUCK_CONFIG_PATH, GOOSE_CONFIG_PATH, OPENDUCK_ADVISOR_CONFIG, ADVISOR_CONFIG_FILE; workspace .openduck/config.yaml, .goose/config.yaml, .openduck/harness.yaml, .goose/harness.yaml, .openduck/advisors.yaml, .goose/advisors.yaml, advisors.yaml; XDG openduck/goose config and advisors files; HOME/.config equivalents then HOME/.openduck/config.yaml and .goose/config.yaml; Windows APPDATA paths; /etc/openduck/config.yaml then /etc/goose/config.yaml.
- `types.rs:389` parses nested harness settings, lowercases session names, and fills absent top-level settings from the root mapping. `:455` file loading and `:463–509` discovery retain the first session entry for each name: **whole-entry precedence**, not per-field merge across files. Parsing and file-read failures become defaults rather than propagated errors. Therefore putting fallible validation only in a serde field here would not produce the required clear surfaced error without changing the loading contract.

## 3. HTTP construction, proxy support, streaming, and coverage

All following references without a prefix are `crates/openduck-providers/src/api_client.rs`:

- `:26–35`: private reqwest `client`, timeout, transport policy, and proxy stored in ApiClient.
- `:280`: old timeout/TLS constructor delegates with proxy None. `:283–315`: `with_timeout_tls_and_proxy` filters trim-empty strings, applies `reqwest::Proxy::all(proxy_url.trim())?`, configures TLS, builds and stores the client. No explicit HTTP/HTTPS-only URL validation or config-key-aware error is present here.
- `:318–325`: `with_proxy` stores the optional proxy and rebuilds; public `proxy()` exposes the stored URL string. It is not proof that a request traversed a proxy and can expose credentials if printed.
- `:336–340`: common `Client::builder` configures connect and read timeouts. `:343–359`: rebuild restores timeout/default headers, transport policy, explicit proxy, and TLS. Header/TLS/policy mutation methods (`:444`, `:457`, `:467–483`) rebuild via that path, so proxy survives rebuilds.
- `:364–406`: Default leaves builder unchanged, HttpsOnly restricts scheme, LoopbackHttp invokes `no_proxy()` plus loopback redirect restrictions, SameOrigin restricts redirects. **Ordering matters:** rebuild applies transport first and then adds the explicit proxy. Thus LoopbackHttp's `no_proxy()` does not by itself prove explicit proxy is suppressed. Preserve policy intent and add a regression if changing this.
- `:570–584`: streaming marks the request and uses bounded response-header/error handling. `:608–618` constructs streaming and ordinary requests from the SAME `self.client.client`; only non-streaming receives a total request timeout. SSE does not create another client in this abstraction. OpenAI passes its streaming capability at `openai.rs:335` and `:845`; Anthropic and Google call `.streaming(true)` at the locations above. Response byte/SSE parsing happens after the send.
- `:641–650`: Debug omits proxy and the reqwest client. No public built-client getter appears in this file. In-module tests can access the private client (`:828`).

**ApiClient is not universal.** Core provider builder sites outside it include `crates/openduck/src/providers/chatgpt_codex.rs:927`, `kimicode.rs:176`, `gcpvertexai.rs:183`, `githubcopilot.rs:292`, `bedrock.rs:293`, `toolshim.rs:604`, `gemini_oauth.rs:42`, `oauth.rs:45`. Concrete streaming counterexample: `chatgpt_codex.rs:911` defines `post_streaming`, `:927` builds a fresh client, `:934` posts Responses, and `:1017–1023` calls it and consumes `bytes_stream`. Any claim of “every provider request” requires auditing these paths, including auth/token and SDK-managed clients where applicable. OAuth additionally has intentional no-proxy handling (`oauth.rs:49`).

### Existing plumbing and limits

- Core already has `ProviderEntry.proxy: Option<String>` with default/skip-if-none at `crates/openduck/src/config/providers.rs:27–28`; normalization trims/drops empties (`:49–56`). `get_provider_proxy` (`:588–626`) resolves provider-specific env overrides first, then a flat NAME_PROXY config key, then providers.<name>.proxy; values can reference a named proxy from `proxies` rather than being URLs.
- Actual core-to-client consumers: `crates/openduck/src/providers/openai_def.rs:125–131`, `anthropic_def.rs:56–62`, `ollama_def.rs:81–87`; Google resolves google/gemini and applies `.with_proxy` (`google_def.rs:57–71`). Declarative provider expansion fills a missing proxy through this helper at `crates/openduck/src/config/declarative_providers.rs:410–414`.
- Provider crate declarative schema has proxy at `crates/openduck-providers/src/declarative.rs:160`; env expansion at `:252–253`; provider-specific proxy env fallback at `:269–284`. Constructors consume it in `openai.rs:956–961`, `anthropic.rs:439–444`, `ollama.rs:335–340`. Google applies it through `google.rs:100–102`.
- Harness `ProjectProviderEntry.proxy` is a separate project data field (`project/config.rs:27`), with example parsing assertions at `:567`, `:588`. It is not automatically a global agent proxy merely because it shares a name with core ProviderEntry.
- Advisor proxy fields are `types.rs:103–112`; harness runtime owns advisor proxy state at `runtime.rs:97`, builder methods at `:231–262`, resolves per-call/per-advisor/global/env settings at `:888–1005`, and puts them into the execution environment at `:1007–1020`. This is subprocess/advisor routing, not shared ApiClient construction.
- Reuse ApiClient's transport machinery, but **do not simply reuse get_provider_proxy unchanged** for the new setting: it is provider-scoped, accepts named proxies/SOCKS, prioritizes env, and returns Option rather than validation errors. Likewise HarnessGlobalSettings has no core client dependency and its permissive parsing hides errors.

### Existing validation and redaction

- `Proxy::all` occurs in ApiClient (`:294`, `:349`) and network probes (`crates/openduck/src/control/network.rs:327`). Probe failure is a probe result, not config validation.
- `crates/openduck/src/config/proxies.rs:10–40` defines ProxyEntry and only trims URL/description. `:50–100` parses named proxy maps, skipping malformed entries; it does not validate HTTP/HTTPS scheme/host. Existing SOCKS support is intentional: workspace reqwest enables `socks` (`Cargo.toml:55`), tests use socks5 (`config/providers.rs:1166`, `config/proxies.rs:173`), and advisor docs show SOCKS. Do not tighten these older settings globally just to constrain the new key.
- `crates/openduck/src/control/network.rs:103–112` private `public_url` parses with Url, removes username/password/query/fragment, returns `Invalid URL` if unparseable. Probe endpoint redaction repeats this at `:336–342`. Useful redaction behavior, but private and not a malformed-input-preserving validator.
- `crates/openduck-provider-types/src/errors.rs:218`, `:236` have tests for URL redaction in provider errors. These are relevant regression patterns, not proof config errors sanitize raw input.

## 6. Concrete proposed implementation contract

1. Add a top-level lowercase YAML `proxy` key to the core dynamic config API (a fallible `Config::get_proxy` accessor, with literal `proxy` key). There is no core schema struct to add a serde field to. If introducing a small deserialized settings struct, use `#[serde(default, skip_serializing_if = "Option::is_none")] pub proxy: Option<String>`; no camel alias is needed for a single word. Do not add an unused TuiSessionDefaults field just to satisfy a struct-field expectation.
2. Put reusable strict URL parsing in a provider-level transport helper, e.g. `crates/openduck-providers/src/api_client.rs` (or a dedicated proxy module re-exported by that crate), with the core accessor attaching config-key context. Accept only explicit http/https scheme, a host, valid port, and optional URL user/password. Normalize surrounding whitespace; missing/null/trim-empty gives None. Reject schemeless input and SOCKS for this new key without changing legacy SOCKS settings. Propagate malformed types/URLs; never `.ok()`/default them away.
3. Use existing `ConfigError::DeserializeError` (`base.rs:62–67`) with a sanitized message, e.g. `Invalid config key 'proxy' value 'http://[redacted]@proxy.example:bad': expected an HTTP or HTTPS proxy URL with a host and valid port`. Remove userinfo before showing an offending value, even when URL parsing fails; never append raw reqwest/serde diagnostics containing credentials. A conservative malformed-input sanitizer can remove the authority userinfo through its last @; fully redact unrecognizable potentially credential-bearing values. For a valid URL follow public_url's removal of query/fragment as well. Include regression tests with invalid credential-bearing input.
4. Apply the parsed value at provider client construction using ApiClient's existing explicit proxy argument / with_proxy, and retain it through rebuild. To guarantee all model requests, route every remaining direct provider builder through a common configured client factory (including ChatGPT Codex post_streaming), or explicitly implement the same resolution in those builders. Do not put per-request proxy logic in either agent loop. ApiClient's streaming path already shares transport; avoid a second streaming client.
5. Define precedence before implementation: explicit new file setting must precede standard HTTP_PROXY/HTTPS_PROXY/ALL_PROXY discovery; absence/empty/null leaves no explicit ApiClient proxy so existing env behavior can remain fallback. Here “disabled” means the optional **setting** is disabled, not necessarily forced direct networking. If empty/null is intended to disable env proxies too, represent presence separately from None and call no_proxy; that is a materially different contract. Also specify interaction with existing provider-specific proxy overrides: preserving them for compatibility versus making the new global key authoritative cannot both be assumed silently. Generic get_param env-first behavior and get_provider_proxy env-first behavior must not accidentally decide this contract.

No universal request coverage, validation behavior, or runtime transport success was inferred from a stored proxy string. These require implementation and the observable tests above.
