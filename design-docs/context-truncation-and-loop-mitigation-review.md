| P1 | 每次工具调用追加消息时，忽略了同时返回的可见助手文本 | 保存响应的 `text` 字段，并在历史重放中恢复；不复制隐藏 thinking 或伪造模型结论 |

## 2. 对原方案的必要修正

1. **不要将 `max_messages` 强行钳制到至少 200。** 这会破坏显式配置和兼容入口 `prune_context_messages`。仅调整默认值，保留调用者提供的小上限。为保留工具调用/结果配对，最终数量可能略高于上限。
2. **Token 触发已存在。** 当前实现不是从零引入 token 驱动。继续使用调用者提供的模型上限与现有 0.8 水位；`None` 保持只按消息数触发的原有语义，不臆测 64K/128K 容量。
3. **压缩消息数与真正的 token 预算不同。** 当前估算约为文本字节数除以四，尚未完整计算工具 schema、独立 system prompt、回复预算和不同模型分词。调整消息数量不能保证所有请求都低于模型窗口。
4. **不能从已经丢弃的隐藏推理中恢复结论。** 本次保留可见助手文本与实际工具证据；建议模型主动将关键结论写入笔记。
5. **重复读取不等于任务失败。** 同文件不同范围、不同检索模式是合理操作。只有相同观察请求在最近十次观察中出现至少四次，且其间没有成功写入或执行可识别的修改/验证命令，才提醒调整策略。提醒最多每十轮发一次；成功写入或验证命令重置检测与提醒冷却。
6. **不能把收到提醒当作成功完成。** 达到回合上限仍是 `Cancelled`；剩余五轮时提醒整理结论。提醒不改变现有最终回答、评审或输出验收规则，也不能保证模型会收敛。
7. **不将“停止所有检索”作为通用规则。** 诊断任务可以在证据充分后结束，也应允许必要的定点复查。
8. **删除没有测量依据的承诺。** “Token 利用率提升 300%+”“保证 50 轮收敛”“彻底杜绝循环”均需要对照实验，不能作为已达成结果。

## 3. 已实现的细节与边界

### 摘要透传与连续压缩

`HarnessMessage` 新增可选 `compacted_facts`。普通消息不输出该字段；旧序列化消息可通过默认值继续读取。Rust 中直接使用结构体字面量的调用者需要补上此字段；仓库中已知的调用点已更新。

结构化状态按类别限制数量：笔记最多 8 条、助手陈述和工具证据各最多 8 条、计划最多 2 条、测试结果与错误各最多 4 条、探索/修改路径各最多 64 项。文本在提取时截取。旧版无结构化字段的摘要提供有界文本兜底。最新同路径笔记替换旧版本。

这是确定性的有界事实保留，不是 LLM 语义总结；输出片段可能不包含长文件中间的重要内容，保留条目也会随容量限制被淘汰。读取过某文件本身不代表排查完成。工具证据明确标记为片段，而不是新的高优先级指令。

### 提醒与笔记路径

复用并下移原有任务 ID 清理与笔记路径函数，Bridge 与运行时使用同一命名规则。子任务使用父任务 ID 生成 `.agent/notes-plan-<task-id>.md`，避免提醒模型写错文件。

重复调用提醒受现有 `with_circuit_breaker(false)` 控制。笔记检查与回合预算提醒独立运行。未知扩展工具不参与观察请求识别，因此检测覆盖并不完整；不据此自动终止任务。

本次修改位于共享 Harness 循环和 Provider 桥接层，没有修改旧 agent loop 或 state-machine loop 的专属实现。
